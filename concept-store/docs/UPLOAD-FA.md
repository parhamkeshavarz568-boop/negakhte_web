# راهنمای آپلود سایت روی هاست

## ۰) پیش از آپلود

یک فایل آماده برای آپلود ساخته می‌شود:

```
python build/make_upload.py
```

نتیجه: `concept-store/dist/concept-store-upload.zip` (حدود ۵۲ مگابایت).
این دستور اول سایت را چک می‌کند و اگر خطا داشته باشد، زیپ نمی‌سازد.

> **حالت پیش‌نمایش.** تا وقتی نام فروشگاه و راه‌های تماس نهایی نشده‌اند، همهٔ صفحه‌ها
> `noindex` دارند؛ یعنی می‌شود سایت را آپلود کرد و دید، ولی گوگل آن را با نام موقت
> ثبت نمی‌کند. روز افتتاح، در `build/site_config.py` مقدار `"launch"` را `True` کنید،
> دوباره بسازید و دوباره آپلود کنید.

## ۱) کجا آپلود شود؟

فقط **محتویات** پوشهٔ `public/` روی هاست می‌رود؛ زیپ هم دقیقاً همین را دارد.
`build/` و `docs/` و بقیه ابزار ساخت‌اند و نباید روی هاست بروند.

بعد از باز کردن زیپ، باید این شکل باشد:

```
public_html/
├── index.html
├── .htaccess
├── 404.html
├── robots.txt
├── assets/
├── candles/
├── ceramics/
└── ...
```

این شکل **غلط** است و سایت باز نمی‌شود:

```
public_html/
└── public/        ❌
    └── index.html
```

### اگر سایت باید داخل یک پوشه باشد

مثلاً `example.ir/shop/` (اگر روی دامنهٔ دیگری از همین مجموعه می‌نشیند):

۱. در `build/site_config.py` بنویسید `"base": "/shop/"`.
۲. `python build/build.py` و بعد `python build/make_upload.py`.
۳. در هاست، داخل `public_html` یک پوشهٔ `shop` بسازید و زیپ را **داخل همان** باز کنید.

همهٔ لینک‌ها، عکس‌ها و صفحهٔ ۴۰۴ خودشان با این پوشه جور می‌شوند.

## ۲) آپلود با cPanel (یا DirectAdmin)

۱. وارد پنل شوید → **File Manager** → پوشهٔ `public_html` (یا پوشهٔ `shop`).
۲. **Settings** → تیک **Show Hidden Files (dotfiles)** را روشن کنید؛ بدون آن فایل
   `.htaccess` دیده نمی‌شود.
۳. اگر سایت قبلی آنجاست، اول از آن پشتیبان بگیرید (زیپ کنید و دانلود کنید)، بعد پاکش کنید.
۴. **Upload** → فایل `concept-store-upload.zip`.
۵. روی زیپ راست‌کلیک → **Extract** → همان پوشه.
۶. خودِ زیپ را پاک کنید.
۷. چک کنید `index.html` و `.htaccess` مستقیم داخل پوشه باشند، نه یک پوشه پایین‌تر.

## ۳) آپلود با FTP (FileZilla)

۱. اول زیپ را روی کامپیوتر خودتان باز کنید.
۲. در FileZilla: **Server → Force showing hidden files** را روشن کنید.
۳. همهٔ محتویات را به `public_html/` بکشید. حدود ۱۷۵۰ فایل است و چند دقیقه طول می‌کشد.

## ۴) بعد از آپلود — چهار چک

| چه چیزی را باز کنید | باید چه ببینید |
|---|---|
| صفحهٔ اول | عکس گوشهٔ آفتاب‌گیر با تیتر بزرگ، و زیرش ویترینِ هشت مجموعه |
| `/candles/` | قفسهٔ شمع‌ها با عکس |
| یک آدرس بی‌معنی، مثل `/xyz/` | صفحهٔ «این قفسه خالی است»، نه صفحهٔ خطای هاست |
| `/candles` (بدون `/` آخر) | خودش به `/candles/` برود |

اگر صفحه بی‌رنگ و بدون فونت آمد، یعنی فایل‌ها یک پوشه پایین‌تر رفته‌اند (بند ۱).
اگر صفحهٔ ۴۰۴ هاست آمد، یعنی `.htaccess` آپلود نشده (بند ۲، قدم ۲)، یا هاست
nginx است و `.htaccess` را نمی‌خواند؛ سایت کار می‌کند، فقط ۴۰۴ و کش ندارد.

## ۵) روز افتتاح

در `build/site_config.py`:

- `name_fa` / `name_en`: نام واقعی، و `name_is_placeholder` را `False` کنید
- `CONTACT`: اینستاگرام، تلگرام، واتساپ، تلفن (هر کدام که دارید)
- `url`: دامنه، مثلاً `"https://example.ir"`
- `launch`: `True`

بعد:

```
python build/build.py
python build/validate.py      # فهرست «Launch blockers» باید خالی شده باشد
python build/make_upload.py
```

و زیپ تازه را مثل بالا آپلود کنید.

### HTTPS

در `.htaccess` اجباری‌کردن https **عمداً خاموش** است. اگر گواهی SSL نصب نباشد و
https اجباری شود، کل سایت از دسترس خارج می‌شود. اول گواهی بگیرید (در cPanel:
**SSL/TLS Status → AutoSSL**؛ برای دامنهٔ `.ir` ارائه‌دهنده را **Let's Encrypt**
بگذارید، چون Sectigo برای `.ir` گواهی نمی‌دهد). وقتی `https://` با قفل سبز باز شد،
دو خطِ مشخص‌شده در `.htaccess` (قالبش در `build/templates/htaccess.tpl`) را از حالت
توضیح در بیاورید و `url` را با `https://` بنویسید.
